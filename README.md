# personal-hub

Личный «второй мозг» на двоих-троих: Telegram-бот, куда кидаешь всё подряд текстом, и веб-дашборд, который
показывает задачи, проекты, календарь и утренний брифинг на одном экране. Self-hosted, один контейнер,
SQLite, LLM — Anthropic API.

> Скриншот: `docs/screenshot.png` (добавьте свой — в репозитории его нет).

## Что умеет

**Фаза 1a — ядро и бот**
- свободный текст → Claude Haiku раскладывает на *задачу / проект / «подумать» / заметку*, достаёт срок
  («до пятницы» считается по местной дате) и контур; тип меняется одной кнопкой;
- проект → Claude Sonnet предлагает 3–7 подзадач, `✅` создаёт их;
- разделы («Отпуск», «Ремонт»), шаринг записи конкретному человеку или пространству «Семья»;
- несколько пользователей по одноразовым приглашениям `/invite` (24 ч); незнакомцам бот молчит;
- утренний брифинг по расписанию у каждого свой, с повторами при сбое модели и «сырым» запасным вариантом;
- дневной лимит токенов на пользователя, маскирование номеров карт и паспортов перед отправкой в модель,
  ночной бэкап SQLite.

**Фаза 1c — веб-дашборд**
- вход по одноразовой ссылке из бота (`/web`) или прямо в Telegram как мини-приложение (проверка `initData`);
- экраны «Сегодня» (виджеты), «Задачи», «Настройки»; светлая/тёмная тема, подхватывает цвета Telegram;
- календари Google/Яндекс по секретной ссылке iCal (только чтение, ссылка хранится зашифрованной Fernet),
  события дня — первым разделом брифинга.

## Архитектура

```
             ┌──────────────── один процесс: python -m hub ────────────────┐
 Telegram ◄──┤ bot (aiogram, long polling) ─┐                              │
             │                              ├─► Service ─► access.py ─► SQLite
 браузер/TMA ┤ web (FastAPI+Jinja2+HTMX) ───┘      │       (единственное  │ (aiosqlite,
  (через VPN)│                                    │        место правил   │  миграции)
             │ scheduler (APScheduler): брифинги, │        видимости)     │
             │   сторож, бэкап, синк календарей ──┤                       │
             └────────────────────────────────────┼───────────────────────┘
                     llm.py ─► Anthropic: Haiku (разбор) / Sonnet (подзадачи, вступление брифинга)
                     calendar_ics.py ─► ICS по https, разбор в отдельном процессе с лимитом памяти
```

- **Один процесс, один event loop**: бот, веб и планировщик делят базу; никаких очередей и брокеров.
- **Слой доступа** `hub/access.py` отдаёт SQL-условие видимости; остальные модули своих правил не пишут.
- **Бот и веб — тонкие обёртки** над `hub/service.py`, логика тестируется без Telegram.
- **ICS-песочница**: только `https`, запрет приватных/loopback адресов (каждый DNS-ответ и редирект),
  лимиты размера, времени и памяти; парсинг вынесен в дочерний процесс.

## Быстрый старт (локально)

1. Создайте бота у [@BotFather](https://t.me/BotFather), узнайте свой Telegram ID (например, у @userinfobot).
2. `cp .env.example .env` и заполните:
   - `BOT_TOKEN` — токен бота; `ANTHROPIC_API_KEY` — ключ Anthropic;
   - `ADMIN_TG_ID` — ваш Telegram ID: первый пользователь и админ, создаётся при старте;
   - `CONNECTIONS_KEY` — ключ Fernet (команда генерации — в `.env.example`);
   - `WEB_BASE_URL` — `http://localhost:8080` для разработки, `https://desk.example.com` в бою;
   - необязательные: `BOT_USERNAME`, `WEB_PORT`, `SESSION_DAYS`, `DB_PATH` / `BACKUP_DIR` (локально укажите
     путь вроде `./data/hub.db`), `BRIEF_TIME`, `DAILY_TOKENS_IN/OUT`, `MODEL_FAST` / `MODEL_SMART`,
     `ALLOWED_TG_IDS` (белый список), `USER_NAMES` (`tg_id=Имя,…`).
3. Стили и htmx: `bash scripts/fetch_assets.sh && .tools/tailwindcss -i styles/app.css -o hub/web/static/app.css --minify`
   (бинарники закреплены по sha256 в `scripts/assets.lock`).
4. `uv sync`, затем `uv run python -m hub`. Напишите боту `/start`.
5. Остальных зовите командой `/invite` — бот даст одноразовую ссылку.

Тесты и линтер: `uv run pytest -q`, `uv run ruff check`. Мини-приложению Telegram нужен публичный https;
локально проверяйте веб через ссылку `/web`.

## Деплой

`docker compose up -d --build`: многостадийный `Dockerfile` сам собирает CSS, образ без root, лимит памяти
384 МБ, порт не публикуется — веб доступен только во внешней docker-сети `proxy` для вашего nginx.
Конфиги nginx (`ops/nginx/`) пускают только подсети VPN (`allow <VPN_SUBNET>; deny all`), TLS — certbot.
Пошагово, с проверками и откатом: [`ops/DEPLOY.md`](ops/DEPLOY.md).

## Как адаптировать под себя

- **Промпты** — константы `CLASSIFY_PROMPT`, `DECOMPOSE_PROMPT`, `BRIEF_PROMPT` в `hub/llm.py`;
  список контуров — `CONTOURS` в `hub/entries.py`; модели — переменные `MODEL_FAST` / `MODEL_SMART`.
- **Виджет на «Сегодня»** — шаблон `hub/web/templates/partials/widgets/<имя>.html`, функция-сборщик данных
  в словаре `WIDGETS` (`hub/web/routes_pages.py`) и место в сетке `hub/web/templates/dashboard.html`.
- **Новый коннектор** — новый `kind` в таблице `connections` (миграция в `migrations/`, там `CHECK`),
  загрузчик по образцу `hub/calendar_ics.py`, задача синхронизации в `hub/scheduler.py`, форма в «Настройках».
- **Стиль** — токены темы `hub-light` / `hub-dark` в `styles/app.css` (daisyUI 5 + Tailwind 4); каждый цвет
  идёт цепочкой `var(--tg-theme-…, <свой цвет>)`, поэтому внутри Telegram побеждают цвета клиента.

## Как это построено

Проект целиком написан ИИ-агентом для владельца-непрограммиста, и процесс — часть ценности:
1. грилл требований → спецификация [`docs/superpowers/specs/`](docs/superpowers/specs/) с пометками
   «решено владельцем» / «выбор строителя»;
2. исследование аналогов и дизайна [`docs/research/`](docs/research/);
3. планы по фазам [`docs/superpowers/plans/`](docs/superpowers/plans/): задачи с интерфейсами, падающими тестами
   и «Review Focus» — сценариями, которые обязаны быть покрыты;
4. subagent-driven development: каждая задача — отдельный субагент, TDD, ревью после каждой задачи;
   мелкие отложенные замечания — в [`docs/backlog.md`](docs/backlog.md).

## Дорожная карта (из спеки)
