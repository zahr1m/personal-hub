## 0. Итог после двух проходов (27.10)

**Что поменялось по сравнению с первым проходом:**
1. **Pico CSS отпадает.** По второму проходу: «v2.1.1 is the final release» на picocss.com, репозиторий заархивирован 4.10.2026. Моя рекомендация «Pico + свои токены» снимается.
2. **Новая рекомендация — daisyUI 5 + Tailwind 4 (standalone CLI, без Node)**; на старте можно подключить `daisyui.css` с CDN (~63 kB сжатым). Почему: компоненты на классах (HTMX-свопы ничего не ломают), есть `dock` (нижняя навигация), `toast`, modal на нативном `<dialog>`; тема целиком в CSS-переменных и переназначается на `--tg-theme-*`. Запасной вариант — Basecoat (вид shadcn, тоже Tailwind). Web Awesome не берём: shadow DOM мешает HTMX и формам.
3. **Шкала срочности сроков — из LubeLogger:** `NotUrgent → Urgent → VeryUrgent → PastDue`, срочность считается на лету от `days_left`, **уведомление — только при смене уровня**, а не каждый день. Ложится на наш реестр (§6.3 спеки): пороги `notice_days` (наш `renew_by`), 7 дней, просрочено.
4. **Почта — модель Inbox Zero + журнал с обратным действием:** `suggestion → (одобрить | всегда → rule с версией | отменить)`, `action_log` с `inverse_json` и проверкой «письмо всё ещё в том состоянии», откат кнопкой. Готового open-source с нашей тройкой «одобрить / всегда / отменить» **нет** — проектируем сами. Лицензия Inbox Zero, по вторичным данным, AGPL с ограничениями — код не берём, только идеи.
5. **Вход в мини-приложении Telegram:** `initData` → `POST /auth/tma` → проверка HMAC, `auth_date` (5–60 мин) и что пользователь зарегистрирован → наш токен. Токен передаём **и cookie, и заголовком** `Authorization` (через `htmx:configRequest`): в Telegram Web/Desktop мини-приложение живёт в iframe, и cookie там третьесторонняя — сообщество фиксирует, что она не доходит. CSP `frame-ancestors 'self' https://web.telegram.org`.
6. **Всё на одном домене.** С Bot API 10.2 (14.07.2026) методы мини-приложения с чужого origin блокируются — никаких `auth.` поддоменов, только `desk.example.com`.
7. **Сертификат.** Нужен настоящий публичный TLS — самоподписанный в WebView не откроется. У нас схема как у соседних сервисов на хосте: публичная A-запись + certbot + allowlist VPN в nginx, HTTP-01 для `/.well-known` уже открыт — **подходит, DNS-01 не нужен** (вывод строителя по конфигу сервера 26.10).
8. **В обычном браузере** вход остаётся по ссылке из бота (`/web`, спека §20.1). Альтернатива из второго прохода — «Log In with Telegram» на OpenID Connect (старый Login Widget в архиве) — на потом, если ссылка надоест.

**Решения по экранам (сводно):**
- Нижняя панель из 4 вкладок: **Сегодня · Задачи · Почта · Документы**; настройки — иконкой в шапке. Внутри Telegram добавить к отступу снизу `safeAreaInset.bottom`.
- «Сегодня»: 3–5 карточек по срочности (просрочено → встречи в ближайшие 2 часа → почта, ждущая решения → документы VeryUrgent), в карточке одна строка-вывод и одно главное действие; мелко серым «обновлено N мин назад». Каждая карточка грузится отдельно (`hx-get` + `hx-trigger="load, every 10m"`, паттерн Glance).
- Бейдж срока — число дней + цвет, цвет всегда продублирован текстом: серый «через 45 дн.», жёлтый «через 12 дн.», красный «через 3 дн.», красный залитый «просрочено 2 дн.».
- Очередь почты: «отправитель · тема · действие · почему»; кнопки 44–48 px «Одобрить» (главная) / «Всегда» / «Отменить»; свайп — только дублирующий жест (свой код ~40 строк на pointer events, в библиотеках его нет); после решения — тост «Архивировано · Отменить», который **не исчезает сам** (Material 3 для тостов с действием); кнопка «Одобрить всё с высокой уверенностью».
- Журнал: «вчера / сегодня», иконка, кто сделал (я / партнёр / правило №N), «Откатить» пропадает, если откат уже невозможен.
- Зоны нажатия ≥ 44–48 px, строки списков 56–64 px; телефон — одна колонка, ПК — 2–3 колонки.
- Высота экрана — `var(--tg-viewport-stable-height, 100dvh)`, не `100vh`; безопасные зоны — `safeAreaInset` + `contentSafeAreaInset` с fallback на `env(safe-area-inset-*)`.
- Тема: свои токены через цепочку `var(--tg-theme-…, <наш цвет>)` + `prefers-color-scheme` — в браузере работают наши цвета, в Telegram побеждают цвета клиента.
- HTMX внутри Telegram: `hx-boost` + `hx-push-url` вместо полных перезагрузок; `BackButton` и `MainButton` настраиваются по `data-*` фрагмента на `htmx:afterSettle`; `openLink()` — только по клику.

**Что заносим в спеку при плане 1c** (не сейчас — сейчас идёт 1a): daisyUI вместо «HTMX без библиотеки»; вход в мини-приложении через `initData` в дополнение к ссылке `/web`; токен в заголовке; один origin; шкала срочности и «уведомлять при смене уровня» для реестра (план 1b).

**Ещё из второго прохода, на будущие планы:** модель задач Vikunja (проект → подпроект, повторы, CalDAV) — ориентир для разделов; Homebox — «фиксированные поля + произвольные» для документов и гарантий; Wallos — «следующая дата + цикл + за сколько дней напомнить» для аренды и подписок; модель коннекторов со статусами `ok | degraded | auth_expired | error | disabled`, «синхронизировано N мин назад», кнопки «Переподключить» / «Проверить сейчас» — для страницы «Настройки». Полный текст второго прохода в репозиторий не входит.

**Ненадёжно:** лицензии Inbox Zero и Planka; цифры звёзд; дизайн реальных продуктов (Sunsama, Things, Cozi и др.) по первоисточникам не изучался ни в одном проходе; поведение cookie в WebView Telegram — опыт сообщества, не официальная документация.

## 3. Как строить экран (паттерны)

Первый экран должен за секунду отвечать на три вопроса: **«что требует внимания сейчас», «что дальше сегодня», «что скоро истекает»** (вывод из разбора Sunsama, Akiflow, Todoist Today).

1. **Шапка:** «Доброе утро» + дата, одна строка статуса («2 просрочено · 3 на неделе»), одна кнопка «Добавить».
2. **Требует внимания:** просроченное и сегодняшнее; сдержанный цвет предупреждения и **текстовые метки** («Просрочено», «Сегодня», «Ждёт решения») — не только цвет. У строки одно главное действие.
3. **Сегодня:** задачи и события календаря одной лентой по времени, визуально различимы; отметить / перенести прямо из строки.
4. **Скоро истекает:** группы «7 дней» и «30 дней», ближайшее развёрнуто, остальное свёрнуто; в строке — название, дата, сумма, действие («Продлил», «Не продлеваю»).
5. **Очередь предложений почты — отдельно от задач**, чтобы предложения ИИ не смешивались с подтверждённым: контекст письма, предлагаемое действие, короткая причина; «Одобрить» — главная кнопка, «Всегда» и «Отменить» — второстепенные; отмена сразу после действия.
6. Мобильная вёрстка: одна колонка, липкая шапка, нижняя навигация; пустые секции сворачиваются; порядок по срочности, а не по типу данных.
7. Цвет сроков: нейтральный → янтарный (подходит) → красный (просрочено), всегда с подписью.

## 4. Чем верстать (FastAPI + Jinja2 + HTMX, без React)

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Pico CSS** | без сборки, крошечный, семантичные теги, светлая/тёмная тема сама по системе, CSS-переменные | мало готовых виджетов: вкладки, тосты, бейджи — дописать самим |
| **DaisyUI + Tailwind standalone CLI** | много готовых компонентов (карточки, вкладки, бейджи, тосты, модалки), темы | нужна сборка CSS (бинарник CLI в Docker-сборке), классы-утилиты в шаблонах |
| **Web Awesome** (преемник Shoelace) | 90+ веб-компонентов, работает в чистом HTML | JS-рантайм компонентов, тяжелее |
| Basecoat UI, Franken UI | стиль shadcn без React | моложе, зрелость проверить |
| Open Props | токены дизайна | не компоненты — всё собирать самим |

**Рекомендация строителя (26.10, снята 27.10 — см. §0: Pico заархивирован):** **Pico CSS + свой небольшой слой токенов**. Причины: без сборки (один контейнер, простой Dockerfile), лёгкий, и его CSS-переменные напрямую перекладываются на тему Telegram (`--tg-theme-bg-color` и др.), так что одна страница выглядит родной и в браузере, и в мини-приложении. Если при макетировании окажется, что не хватает готовых компонентов, — переход на DaisyUI.

## 5. Мини-приложение Telegram — что учесть

- Подключить `telegram-web-app.js` в `<head>` до остальных скриптов; работать через `Telegram.WebApp`.
- Брать цвета из `themeParams` (CSS-переменные `--tg-theme-*`) и реагировать на смену темы.
- Учитывать высоту окна и безопасные зоны — без фиксированных раскладок, которые залезают под кнопки Telegram.
- `BackButton` / `MainButton` — по месту, через их события.
- **Личность пользователя — только после проверки `initData` на сервере** (HMAC-SHA256 с ключом от токена бота); `initDataUnsafe` для входа не годится. Это может заменить вход по ссылке `/web` внутри Telegram.
- **Нужен HTTPS с настоящим сертификатом** — у нас certbot уже есть.
- **Доступ только через VPN:** заработает, если сам клиент Telegram на телефоне ходит через VPN. Подтверждает ограничение из спеки §20.12.
